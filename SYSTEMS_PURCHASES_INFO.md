# 📊 Системы покупок в боте

## Общая информация

В боте существует **4 основные системы покупок**, которые работают для разных категорий пользователей и с разной степенью интеграции с платежной системой.

---

## 1. 🏙️ Покупка городов (исполнители) - НОВАЯ СИСТЕМА

### Описание
Исполнители могут покупать подписки на дополнительные города для получения заказов.

### Реализация
- **Таблица БД:** `worker_city_subscriptions`
- **Модель:** `WorkerCitySubscription`
- **Файлы:** `app/handlers/worker.py` (строки ~4015-4270)

### Тарифы
- 1 город - 90₽
- 2 города - 180₽
- 3 города - 270₽
- 4 города - 360₽
- 5 городов - 450₽
- 10 городов - 900₽
- 20 городов - 1800₽

### Периоды подписки
- 1 месяц
- 2 месяца (скидка 5%)
- 3 месяца (скидка 10%)
- 6 месяцев (скидка 20%)
- 12 месяцев (скидка 30%)

### Платежная система
**⚠️ ЗАГЛУШКА** - реальные платежи не интегрированы
- Функция: `confirm_city_purchase()` (строка 4187)
- Комментарий в коде: `# Здесь должна быть интеграция с платежной системой`

### Статус
✅ Полностью рабочая система (но без реальных платежей)

---

## 2. 💼 Покупка подписки на направления работы (исполнители) - СТАРАЯ СИСТЕМА

### Описание
Старая система покупки подписки через `SubscriptionType` для получения доступа к откликам на объявления.

### Реализация
- **Таблица БД:** `subscription_types`
- **Модель:** `SubscriptionType`
- **Связь:** `WorkerAndSubscription.subscription_id`
- **Файлы:** 
  - `app/handlers/worker.py` (строки 2156-2317)
  - `app/data/database/models.py` (строки 1407-1511)

### Функции покупки
- `send_invoice_buy_subscription()` - отправка инвойса (строка 2188)
- `success_payment_handler()` - обработка успешного платежа (строка 2283)

### Платежная система
**✅ РЕАЛЬНЫЕ ПЛАТЕЖИ** через Telegram Payments
- Использует `config.PAYMENTS`
- `answer_invoice()` с `provider_token=config.PAYMENTS`
- Обработчик `successful_payment`

### Параметры подписки (SubscriptionType)
- `count_work_types` - количество доступных направлений
- `count_guaranteed_orders` - количество гарантированных откликов
- `unlimited` - безлимит на отклики
- `notification` - уведомления
- `price` - цена
- `count_cites` - количество городов (устаревшее, не используется)

### Статус
⚠️ Активна, но считается устаревшей (есть новая система городов)

---

## 3. 💬 Покупка контактов/жетонов (исполнители)

### Описание
Исполнители покупают "жетоны" (контакты) для получения телефонов заказчиков после отклика на объявление.

### Реализация
- **Таблица БД:** `workers` (поле `purchased_contacts`)
- **Поле:** `worker.purchased_contacts` - количество купленных контактов
- **Поле:** `worker.unlimited_contacts_until` - безлимитный доступ до даты
- **Файлы:**
  - `app/handlers/worker.py` (строки 4777-4951)
  - `app/handlers/anonymous_chat.py` (строки 2465-2665)

### Тарифы
- 1 контакт - 190₽
- 2 контакта - 290₽ (-24%)
- 5 контактов - 690₽ (-27%)
- 10 контактов - 1190₽ (-37%)
- Безлимит 1 месяц - 1990₽
- Безлимит 3 месяца - 4490₽
- Безлимит 6 месяцев - 6990₽
- Безлимит 12 месяцев - 10990₽

### Платежная система
**⚠️ ЗАГЛУШКА** - реальные платежи не интегрированы
- Функция: `confirm_contact_purchase()` (строка 4897)
- Функция: `confirm_token_purchase_` (строка 2544 в anonymous_chat.py)
- Комментарий в коде: `# Здесь должна быть интеграция с платежной системой`

### Как работает
1. Исполнитель делает отклик на объявление
2. Система предлагает купить контакты заказчика
3. После покупки контакты передаются исполнителю
4. Списывается 1 жетон из `worker.purchased_contacts`

### Статус
✅ Рабочая система (но без реальных платежей)

---

## 4. 📝 Покупка объявлений (заказчики)

### Описание
Заказчики покупают дополнительные объявления для размещения заказов сверх лимита.

### Реализация
- **Таблица БД:** `customers` (поле `abs_count`)
- **Файлы:** `app/handlers/customer.py` (строки 290-495)

### Функции покупки
- `buy_single_advertisement()` - покупка одного объявления (строка 291)
- `send_invoice_buy_subscription()` - отправка инвойса (строка 377)
- `success_payment_handler()` - обработка платежа (строка 483)

### Платежная система
**⚠️ СМЕШАННАЯ:**
- Реальная оплата через Telegram Payments (строка 313) - для `buy_single_advertisement()`
- Симуляция (заглушка) для разработки (строка 399) - для `send_invoice_buy_subscription()`

### Цена
- Цена берется из `admin.order_price` (настраивается администратором)

### Статус
✅ Рабочая система (с реальными платежами в одной функции, с симуляцией в другой)

## ⚠️ Важные замечания

### SubscriptionType
- `SubscriptionType` используется **ТОЛЬКО** для старой системы покупки подписки на направления работы
- **НЕ используется** для покупки городов (новая система `WorkerCitySubscription`)
- **НЕ используется** для покупки контактов
- **НЕ используется** для покупки объявлений

### Что можно удалить?
- ❌ **SubscriptionType удалять нельзя** - используется в старой системе покупки подписок на направления работы
- ✅ Можно оставить как есть - не мешает новой системе городов
- 🔄 Либо перевести старую систему на ранги (`WorkerRank`) и тогда можно удалить

### Что нужно доработать?
1. **Покупка городов** - добавить реальные платежи (сейчас заглушка)
2. **Покупка контактов** - добавить реальные платежи (сейчас заглушка)
3. **Покупка объявлений** - убрать симуляцию, оставить только реальные платежи
